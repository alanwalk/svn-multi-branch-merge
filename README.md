# svn-multi-branch-merge

交互式选择源分支、提交版本和多个目标分支，统一合并、汇总后提交。

## Release Notes

### 1.0.1

- 默认配置改为 `~/.svnmbm/config.jsonc`，不再读取当前工作目录的配置。
- 缺少配置时直接报错，显示完整路径、创建提示和 JSONC 示例，不再自动生成配置。
- `local_path` 的相对路径以配置文件所在目录为基准，从任意目录启动均保持一致。
- 新增 GitHub Release 触发的 npm 自动发布流程，使用 Trusted Publishing（OIDC）。

升级提示：将原来的 `config.jsonc` 移到 `~/.svnmbm/config.jsonc`。如果使用相对副本路径，请按新位置调整，或改用绝对路径。Windows 对应 `%USERPROFILE%\.svnmbm\config.jsonc`。

### 1.0.0

- 首次发布 `@alanwalk/svn-multi-branch-merge`，命令入口为 `svnmbm`。
- 支持交互选择、指定 revision 和全合并，以及多分支并行检查、清理、合并和提交。
- 支持各目标独立的 YAML ignore 规则、`ignore-on-commit` 保护和异常统一确认。

## 安装与配置

命令行入口为 `svnmbm`。安装发布包并配置 `~/.svnmbm/config.jsonc` 后，可在任意目录运行：

默认只读取用户主目录的 `~/.svnmbm/config.jsonc`（Windows 为 `%USERPROFILE%\.svnmbm\config.jsonc`），不读取当前目录配置。文件不存在时会报错退出，显示完整路径和 JSONC 格式示例，不自动创建。可将仓库的 `config.example.jsonc` 复制到该位置，再填写 SVN 副本路径和分支关系。`local_path` 推荐使用绝对路径；相对路径以配置文件所在目录为基准。

```powershell
npm install -g @alanwalk/svn-multi-branch-merge
svnmbm
svnmbm cn-dev
svnmbm cn-preview "99644,99650-99655"
```

本地开发可执行 `npm run build` 后使用 `npm link` 注册命令。`npm pack` / `npm publish` 会自动构建，包内包含 `dist`，不包含本地分支路径配置。

## 运行

需要 Node.js/npm 和 PATH 中可用的 SVN 客户端。在仓库根目录执行：

```powershell
npm ci
npm run dev
```

`npm run dev` 使用 `tsx` 直接运行 TypeScript，无需提前编译；原有 `npm start` 同样可用。修改源码后重新运行即可生效。

如需运行编译产物：

```powershell
npm run build
node dist/main.js
```

分支路径、启用状态和树形关系在 `~/.svnmbm/config.jsonc` 中配置，支持 `//` 行注释、`/* ... */` 块注释和尾随逗号。读取配置不会重写或移除注释；语法错误会提示行列位置。提交信息自动生成，不询问或读取提交信息模板：

```text
Merged revision(s) 96908, 96911 from trunk:
第一个版本的完整原始提交日志（含链接和换行）
........
第二个版本的完整原始提交日志
........
```

版本按升序排列，保留各版本完整正文，不去重或截断。源名称取实际仓库相对路径，例如 `trunk` 或 `branches/release`。手动范围仅支持正向合并，读取对应范围的日志并排除合并起点；日志读取失败时停止执行。各目标按自己的实际待合并版本生成日志，通过 UTF-8 临时文件传给 SVN，提交结束后清理文件。

## 选择合并版本

### 快速启动

```powershell
# 全合并到源分支所有已启用的一级子分支
npm run dev -- cn-dev
# 指定版本；含空格时使用引号
npm run dev -- cn-dev "12312 , 12314,12316 - 12319"
npm run dev -- cn-dev 99579 --concurrency 6
```

指定源分支后跳过选择步骤及执行前确认。所有目标工作副本检查通过，且合并全部完成、没有失败或冲突记录时，显示汇总后直接提交。任一目标失败或出现冲突（包括已自动解决），整批暂停自动提交，统一询问是否提交成功分支，`--skip-summary-confirm` 也不能绕过。取消时保留合并结果。

工作副本不干净时仍需通过 `y / c / n` 手动处理，不自动清理；`ignore-on-commit` 保护规则不变。无交互终端且需要人工处理或确认时，报错退出并保留变更。源分支不存在、无可用一级子分支或版本参数非法时直接报错。不传源分支则保留原有交互模式。

### 交互选择

选好源分支后，可以选择：

- **近期列表**：勾选最近 30 条提交。
- **手动输入**：支持单个版本、逗号列表和包含首尾的 `-` 区间，可以混用。忽略所有空格，自动去重并升序排列。例如 `12312 , 12314,12316 - 12319` 表示 12312、12314、12316、12317、12318、12319。兼容 `12316:12319` 的 SVN 语义：不含起点，即 12317～12319。
- **全合并**：合并 `--depth empty` 与 `--depth infinity` 查询的 eligible 版本，保留子目录历史部分合并记录，不受近期列表条数限制。固定执行计划生成时的源 HEAD；之后新增的提交留到下次。递归检查可能比 `svnmerge` 默认查询列出更多版本。

手动输入中未修改源分支的版本会跳过并提示。所有模式都按目标剔除已合并版本，提交日志仅包含该目标实际合并的版本。大量版本的日志读取与合并分批执行，最终仍统一汇总确认。

## 选择目标分支

源分支列表仅显示 `tree` 中配置了子节点的分支，不显示叶子分支。没有符合条件的源分支时提示并退出。

目标列表仅显示当前源分支在 `config.jsonc` 的 `tree` 中配置的直接子分支，不展开或合并更深层后代。源节点是全选控制项，本身不会成为合并目标。在源节点按空格可选中或取消全部一级目标；在目标节点按空格仅切换该分支。部分选中显示 `[-]`。

`a` 全选或取消全部一级目标，`i` 反选，Enter 确认。禁用分支不会作为目标；没有可用一级目标时提示并退出。

## 版本过滤与工作副本检查

- 根据每个目标的 SVN mergeinfo 剔除已完整合并的版本；部分子路径已合并的版本仍保留。执行计划显示各分支待合并与剔除版本，更新后再次检查。全部已合并时跳过合并和提交。
- 提交日志的版本号与原始正文同步过滤，不包含该目标已合并的版本。
- 在任何分支开始更新前统一检查工作副本。普通本地修改、未版本控制文件和已有冲突会列出并暂停。输入 `y` 表示手动处理后重新检查，`n` 退出。
- 输入 `c` 会清理**本次选中的所有目标副本**：revert 已跟踪文件的本地改动（含 M、D、缺失、计划新增和普通冲突），删除 `?` 未跟踪文件/目录，再重新检查。此操作会丢弃本地改动；计划新增文件 revert 后成为未跟踪项，也会删除。默认不执行清理。
- 清理保留 `ignore-on-commit` 文件，不遍历目录链接到外部路径，不删除嵌套 SVN 副本。类型阻塞或涉及受保护文件的结构变更仍需手动处理。部分清理失败时显示原因并重新检查，不直接进入合并。
- `ignore-on-commit` 是 SVN changelist 名称。该列表中的非冲突文件允许保留本地修改，并排除在自动提交外。
- 更新或合并触碰该列表中的文件（包括干净文件、文本变化和属性变化）时，一律记为待人工处理冲突。不会自动用 `theirs-full` 覆盖它，也不会自动提交该分支，即使传了跳过确认参数。操作通知与内容/属性快照共同检测变化，提交前再次检查。

## 冲突处理

### 各分支独立 ignore 规则

每个目标副本独立读取根目录的 `svnmerge.yaml`（兼容 `svnmerge.yml`）中的 `ignore`，不继承其他分支配置，也不使用其中的 `workspace`、`from` 或 `commit` 覆盖当前计划。未提供文件表示没有额外规则；无效 YAML 或非法路径会停止该分支。

```yaml
ignore:
  - svnmerge.yaml
  - Doc
  - ResProject/Assets/Resources/CommonData/atlas-config.json
```

规则按副本相对路径精确匹配，并包含目录全部后代，不支持通配符。命中路径的已跟踪改动和冲突直接 revert，不使用 `theirs-full`；新添加文件 revert 后清除，提交前再次恢复并排除。未跟踪的忽略文件保留，工作副本检查及 `c` 清理不会要求删除它们。忽略路径原有的已跟踪本地改动也会被 revert。

配置 ignore 的分支逐 revision 合并并恢复忽略路径，避免上一版本的忽略冲突阻塞后续版本。成功恢复的忽略冲突不触发人工确认；恢复失败则按分支异常处理。分支根目录的 mergeinfo 仍可提交。`ignore-on-commit` 的保留本地修改规则优先，重叠或目录结构变更涉及该列表时停止并要求人工处理。

### 普通冲突

- 更新和合并先使用 `--accept postpone --non-interactive` 收集冲突，再逐路径处理，保留冲突记录供汇总检查。
- 普通文本、属性冲突使用 `svn resolve --accept theirs-full`，选择传入版本的完整内容。
- 树冲突先尝试 `theirs-full`；若仍有树冲突且没有未解决的文本、属性冲突，使用 `--accept working`，保留当前工作副本状态并标记解决。这不保证传入的结构变更已应用，需查看汇总中的路径。
- 执行前已有冲突的分支会跳过，不自动解决历史冲突。更新、合并或状态读取失败的分支不会提交；部分合并结果保留在工作副本中。

## 并发与进度显示

工作副本检查、版本检查、清理和合并共用并发设置，默认最多同时处理 6 个目标分支。每个分支内部的操作仍按顺序执行。可调整并发数：

```powershell
npm run dev -- --concurrency 6
```

检查、清理、合并期间，每个分支收缩为一行最新状态，原地刷新，不逐条刷出文件日志。小窗口优先显示正在运行的分支；重定向输出时只记录各分支最终状态。检查或清理发现问题不影响其他分支继续，本轮全部结束后统一列出详细问题；清理全部结束后才重新检查。合并全部结束后才显示完整汇总并进入提交确认。重复或互相嵌套的目标路径会在修改工作副本前拒绝。

提交阶段共用相同并发数（默认 6），每个分支仅显示一行最新状态，全部结束后统一展示提交结果。单个提交失败不阻塞其他分支；汇总确认及异常强制确认规则保持不变，确认完成后才开始并行提交。

清理、重新检查和版本检查连续执行时共用一块进度区域，切换阶段原地覆盖，每个分支只保留最新状态。遇到问题时先结束刷新、统一显示详情并询问下一步；重定向输出也只记录本轮最后状态。

## 汇总与提交确认

所有分支完成合并尝试后，先展示源分支、版本、时间，再用留有行距的表格展示各目标的状态、变更计数和冲突数。表格下方显示各分支本次合并的 revision（已剔除已合并版本），不展开提交日志正文；未完成的合并会明确标记。完整提交日志仍自动生成并用于实际提交。异常原因、工作副本路径、冲突路径和解决方式单独列出。此时尚未提交。

默认询问是否继续提交，默认答案为否。取消或退出时保留合并结果，不自动回滚。确认后仅提交合并成功且没有剩余冲突的分支，提交前再次检查冲突。

可以跳过汇总后的确认（仍显示汇总，执行前的计划确认保留）：

```powershell
node dist/main.js --skip-summary-confirm
# 或
npm run dev -- --skip-summary-confirm
```

**只要本次汇总包含失败或冲突记录，即使冲突已自动解决，也必须人工确认，跳过参数无效。** 无人交互时不能越过这项确认。

提交仅包含汇总中计划内、且不属于 `ignore-on-commit` 的变更路径，使用显式路径列表及非递归提交，避免目录递归带入被排除的文件。确认期间发现额外本地修改时停止该分支提交。

## npm 自动发布

工作流 `.github/workflows/npm-publish.yml` 在 GitHub Release 发布后运行：安装 SVN、构建、测试、检查打包内容，通过后使用 npm Trusted Publishing（OIDC）发布，不保存 npm token。正式 Release 发布到 `latest`，预发布到 `next`。手动运行工作流只验证，不发布。

npm 包的 Trusted Publisher 应配置为 GitHub 用户 `alanwalk`、仓库 `svn-multi-branch-merge`、工作流文件 `npm-publish.yml`，不设置 Environment。

发布新版本时先更新 `package.json` 和锁文件版本，提交并推送，再为该提交创建并发布同版本的 `vX.Y.Z` Release。标签必须与包版本一致；已发布的 npm 版本不能重复发布。
